# 의사결정 정리 (2026-10-06 ~ 10-07)

무인 매장 이상행동 분류기(정상 / 전도 / 유기 / 절도)를 만들면서 내린 결정과 그 이유, 시도했다가 버린 것, 현재 상태를 한곳에 모았다. 세부 수치와 근거 논문은 `행동인식_분석.md`(11, 13~15장), 실행 기록은 `storeops_ai_fr_evt/output/overnight_summary.md`에 있다.

## 1. 한눈에 보기

| 항목 | 최종 결정 |
|---|---|
| 대상 행동 | 전도(쓰러짐), 유기(쓰레기 투기), 절도 + 정상. 방화·파손·폭행은 데이터 삭제·범위 제외, 싸움·파손은 서비스에서도 제거 |
| 모델 | YOLO11n 사람 추적 → S3D-A(화면 전체) + S3D-C1(사람 크롭) → 스택(표준화 + 로지스틱) → 이진 경보 |

| MVP 판정 | 전도·유기는 MVP 수준, 절도는 후보 알림 수준, 새 장소(강의실) 일반화는 미검증 |

## 2. 지켜야 할 규약 (결정의 전제)

- **데이터 분할(AGENTS.md):** 한 영상의 모든 창은 같은 split. 창 단위 무작위 분할 금지. 같은 촬영 회차·다중 카메라는 한 그룹. 증강은 train만. 공식 validation은 최종 시험용으로 봉인하고 임계값 조정에 반복 사용 금지. test 결과로 설정을 바꾸지 않고, 동결 후 한 번만 평가.
- **방법 선정(CLAUDE.md):** 논문 근거 없는 임의 규칙·패치 금지, 임의 값 금지(임계값·길이는 OOF 탐색으로), 라벨이 없으면 규칙으로 가짜 라벨을 만들지 않는다. 근거가 약한 것은 "근거 약함"으로 표시.
- **평가 규약(문서 02):** Event Precision / Recall / F1, False Alarm / Hour가 필수 지표. 클래스별 P/R/F1, 혼동행렬, train-validation 차이를 기록.
- **행동 정의:** 유기 = 들고 있던 물건을 내려놓고 떠나는 것. 절도 = 물건을 가져가는 것(숨김·반출). 전도 = 바닥에 누운 사람이 일정 시간 이상(쪼그려 앉기·숙이기는 제외).

## 3. 의사결정 타임라인

### 3-1. 출발점 (스펙·데이터·분할)
1. **스펙 01/02 채택.** 파이프라인은 사람 검출 + S3D + 물건/불 탐지기를 병렬로 두는 구조에서 출발.
2. **데이터:** AI Hub 71550(전도), 71549(구매행동: 매장이동·반품), 유기·절도 영상. 유기·절도는 디스크 때문에 H.264 CRF23으로 압축(프레임 수·해상도·fps 검증). 방화·파손·폭행 데이터는 삭제하고 범위에서 제외(사용자 결정).
3. **반품 영상 10fps 오류 발견** → 정상 시간 계산이 크게 틀렸음(260분 vs 실제 78분). `video_sampling.py`로 모든 영상을 정확히 3fps로 뽑도록 고치고 특징을 다시 만듦. 이 전에 나온 반품 기반 OOF는 무효 처리.
4. **분할:** 촬영 날짜 단위 5-fold(`global_split.csv`). 공식 validation과 날짜가 겹치는 학습 영상은 격리(quarantine). 반품은 개발용 정상 풀. 공식 validation(전도 81, 유기 80, 절도 80, 매장이동 101)은 봉인.
5. **"매장 단위 보류 검사(LOSO)는 하지 말자"** (사용자 결정) — 그래서 새 장소 일반화는 측정하지 않았고, 이것이 나중에 강의실 문제로 드러남.

### 3-2. 포즈/MLP 경로를 버리고 S3D 중심으로
- 초기에는 YOLO pose 관절 + MLP로 전도를 판정(관절 높이 정규화 포함). YOLO 관절과 AI Hub 관절의 차이(박스 긴 변 기준 중앙값 0.048, 90분위 0.18)도 측정.
- **사용자 결정:** 런타임은 포즈 없이 S3D 하나로 간다. S3D가 중심이고 MLP는 융합에서 뺀다. 서비스 코드에 붙였던 포즈 어댑터는 되돌림(`archive/service_pose_adapter/`).
- 이유: 서비스(`storeops_ai`)가 이미 화면 전체 S3D 분류기 구조이고, 모델만 교체하는 것이 가장 단순하며 행동(전도·유기·절도)을 한 모델로 동시에 다룰 수 있다.

### 3-3. S3D 파인튜닝 설계
- torchvision S3D(Kinetics-400 사전학습), 4클래스 softmax(정상/전도/유기/절도), 한 체크포인트.
- 입력: 4초 창(3fps 12장 → 24프레임), 224×224, 창 간격 2초(서비스와 동일).
- 학습: 3에폭, AdamW(백본 1e-4, 분류층 1e-3), AMP.
- **클래스 균형:** 행동마다 양성 창을 약 3,000개로 같게 고정. 에폭마다 정상 창을 양성 총수와 같게 뽑음(절반은 같은 영상의 사건 밖 구간, 절반은 정상 풀). 손실은 클래스 가중치(총수/(4×클래스 수))를 곱해서 네 클래스 몫이 정확히 25%씩이 되게 함.
- **장면을 외우지 않게:** 같은 영상 안의 사건 밖 창을 정상으로 포함, 사람 크롭 모델(C1) 병행, 증강(좌우 반전, 크롭, 밝기, C1은 일부 흑백).
- **점수 정의:** 그 행동의 로그 오즈(`logit_c − logsumexp(나머지)`). softmax 확률이 1.0으로 포화되는 문제 때문에 확률 대신 로그 오즈 사용(확률 임계값 = sigmoid(점수)). 점수는 확률이 아니며 보정하지 않았다(필요하면 온도 보정, Guo 2017).
- **임계값 = OOF 탐색(임의 값 금지):** 날짜 5-fold에서 보류 fold를 채점해 이벤트 재현율 ≥0.9를 만족하는 후보 중 오경보 창 비율이 최소인 값. 전도 3.02, 유기 3.12, 절도 2.07(로그오즈).

### 3-4. A / C1 / A+C1 비교 (개발용 OOF, 재현율 약 0.9에서 오경보/시간)

| | A(화면 전체) | C1(사람 크롭) | **A+C1 스택** |
|---|---|---|---|
| 전도 | 1.70 | 1.98 | **1.42** |
| 유기 | 7.62 | 7.66 | **4.46** |
| 절도 | 8.60 | 6.72 | 8.10 |

→ A+C1 스택 채택. 유기에서 이득이 가장 큼(7.6 → 4.5). 서비스 비용은 모델 하나 추가(창당 약 10ms)와 사람 박스 합집합 크롭.

### 3-5. 서비스(`storeops_ai`)에 올리기
- 새 브랜치에서 모델과 판정 규칙만 교체(사용자 결정). 원래 모델(`mc_stage2`)은 건드리지 않아 환경변수로 복귀 가능.
- **서비스 데모에서 발견해 고친 문제:**
  1. "사람이 한 명도 추적되지 않은 창은 분류하지 않음" 조건이 쓰러진 사람을 추적기가 놓친 구간(전도)과 사람이 떠난 뒤(유기)를 건너뜀 → 제거.
  2. 기본 임계값이 0.60 하나 → OOF로 정한 카테고리별 값으로 교체.
  3. 웹캠 스크립트가 8초 창·"프레임 24장 이상" 조건이라 4초 창에서 추론이 시작되지 않음 → 4초 창(12장)으로 수정, 사람 크롭·스택 연결.
  4. 학습하지 않은 싸움·파손·방화 카테고리 제거(카테고리 4개), 분류기 테스트 수정.
- **알림 방식:** 위험도 단계(주의/경고/높음)를 만들었다가 사용자가 "재현율 0.9 기준 이진 경보"로 정리. 단계 코드는 `RISK_LEVELS=1`일 때만 켜짐(기본 끔). 단계 경계의 0.95/0.90/0.42 목표값은 내가 정한 값이라 근거 약함.
- **VLM:** 켜지 않는다. 사건 JSON을 LLM으로 보내 자연어 문구를 만들고, 이후 "그날 무슨 일 있었나" 질의를 위해 DB에 저장하는 계획. 시연은 `QWEN_VLM_BASE_URL=`(빈 값)으로 VLM 호출 없이 실행.
- 최종 모델은 전체 개발 데이터로 한 번 더 학습(`--fold -1`)해서 서비스에 올림.

### 3-6. 후처리: 이동 평균을 켜지 않고 "즉시 알림" 설정으로 간다 (사용자 결정, 2026-10-07)
- **상황:** 같은 A·C1 가중치에서 후처리만 바꿔 두 설정을 공식 validation으로 평가했다. 이동 평균 없음 = 평균 Event F1 **0.891**(3회째 사용), 전도·유기에 이동 평균 m=3 = **0.892**(4회째 사용, 임계값 전도 4.98 / 유기 2.78 / 절도 3.28).
- **이동 평균의 효과와 대가:** 개발 OOF에서 시간당 오경보가 전도 1.89→0.94, 유기 2.60→1.72로 줄지만 **경보가 약 4초 늦어진다.** 평균 Event F1은 0.891 → 0.892로 사실상 같다.
- **결정:** 알림 지연 때문에 **이동 평균을 켜지 않은 현재 설정(0.891)으로 가기로 했다.** 점수가 같은데 알림만 늦어질 이유가 없다는 판단이다. 서비스 설정 파일(`storeops_ai/training/runs/ours_stack/fusion.json`)은 이 결정대로 `smooth: 1`, 전도 4.907 / 유기 4.507 / 절도 3.279이고, `export_fusion.py`의 `SMOOTH`에도 같은 결정이 주석으로 남아 있다. 평활을 켠 0.892는 연구 참고 결과로만 기록한다.
- 같은 가중치이므로 나중에 지연을 감수하기로 하면 설정 파일만 바꾸면 된다(`SMOOTH = {1: 3, 2: 3}`로 다시 내보내기).

## 4. 시도했다가 버린 것 (이유 포함)

| 시도 | 결과 | 버린 이유 |
|---|---|---|
| 포즈 + MLP 전도 판정 | 학습 영상에서 잘 됨 | 런타임에 S3D만 쓰기로 한 사용자 결정, 서비스 구조와 맞지 않음 |
| 연속 K개 창 GRU | 전도 1.37→0.85, 유기 5.0→3.4, 절도 이득 없음 | 서비스에 상태·가중치를 추가할 비용 대비 이득 작음 |
| 물건 탐지기 관계 특징을 스택에 추가 | 절도 8.10→4.4~4.7, 유기는 악화(4.46→4.9~5.6), 전도 변화 없음 | 탐지기가 유기·절도 영상의 사건 물건으로만 학습돼 "장면 표시"가 됐을 가능성(shortcut) 배제 불가 |
| 새 물건 + 사람 떠남 AND 게이트 | 오경보 17~54/시간(S3D 단독 2.97) | 진짜 유기 창을 많이 버림 |
| 프레임 대조(배경 차이) 새/없어진 물건 감지 | 정상 영상에서도 후보 시간당 150건 이상, 재현율을 지키면 오경보가 줄지 않음, 절도 removed 재현율 0.05~0.37 | 구분력 약함(매장 일상 변화가 모두 후보로 뜸). 근거 논문: Porikli 2008, Tian 2011 |
| 후보 분류기(정답 물건 박스로 후보 학습) | 코드만 작성 | 사용자 결정으로 중단 |
| 오토인코더(정상만 학습) | - | 새 환경에서 전부 이상으로 뜰 가능성, 어떤 행동인지 모름, 이미 라벨이 충분. `CLAUDE.md`에도 쓰지 않기로 되어 있음 |
| 위험도 단계 | 단계 경계 정의 | 사용자가 이진 경보로 정리 |

사용자의 방향 정리: **S3D가 놓고 감/가져감을 행동과 함께 학습하고 배경은 사람 크롭이 줄인다.** 보조 규칙·탐지기를 얹지 않는다. 시연은 강의실이라 매장 영상으로 맞춘 부가 특징은 의미가 작다.

## 6. 한계 (결과와 항상 같이 밝힌다)

1. 같은 매장·다른 날짜 평가라서 새 장소(강의실)의 성능은 측정되지 않았다. 강의실 웹캠에서 유기가 뜨지 않았고, 학습 영상은 서비스 CLI·웹캠 경로 모두에서 유기가 잡히므로(0.98 이상) 코드 문제가 아니라 환경 차이로 판단.
2. 공식 validation의 정상은 매장이동뿐이라 오경보는 낙관적이다(반품·손 전달 같은 어려운 정상이 없음). 개발용 OOF 오경보(전도 1.42, 유기 4.46, 절도 8.10)가 더 보수적이다.
3. 최종 모델은 전체 개발 데이터로 학습해 OOF가 없고, 임계값은 fold 모델 OOF 기준이다.
4. 유기·절도는 4초 안에 잡는 비율이 66~68%다.
5. 유기 라벨의 물건은 중앙값 70px(화면 높이의 6%)로 작고, 박스가 바닥이 아니라 선반·계산대 위에 붙은 예도 있다(유기가 "바닥에 놓기"만은 아님).

## 10. 손 크롭(H)·관절 헤드(P) 시도와 v1.0 확정 방향 (2026-10-07~08)

- **시도:** 손목 추적 크롭 S3D(H)와 17관절 GRU(P)를 A+C1에 동적 결합으로 더해 날짜 5-fold OOF(같은 창 50,443개, 반품 제외)에서 비교. 세부 표·한계는 `행동인식_분석.md` §19.
- **결과:** OOF 임계값 기준으로는 오경보가 줄지만(절도 2.27 → 1.48/시간 등) 중첩 임계값 평가에서는 유기가 나빠지고 전도 재현율이 목표 아래로 내려가 일관되지 않았다. 신뢰구간은 아직 없다.
- **판단:** 런타임에 포즈 모델과 세 번째 스트림이 추가되는 비용 대비 이득이 불분명하다. v1.0은 A+C1로 확정하고(사용자 합의 후), H·P는 "채택하지 않음"으로 기록한다.
- **미해결:** 주머니 손 넣기 오경보는 측정되지 않았다. S3D 특징 + 관절 특징 결합 학습(원래 최종 목표 방향)은 미시도이므로 v1.0 이후 실험으로 남긴다. 평가 기준은 먼저 정한다(절도 중첩 오경보 감소 + 재현율 유지, 어려운 정상 영상 필요).
- **데이터 정리:** 캐시 점검 결과 학습·공식 validation의 사용 영상은 캐시가 모두 있다(`audit_features.py`). 영상(mp4) 삭제 전 확인 사항: 라벨은 영상 폴더와 분리됨, 분할 파일 `data/global_split.csv`는 보존, 격리된 영상은 현재 쓰지 않지만 규칙이 바뀌면 쓸 수 있어 삭제 여부를 사용자가 정한다. 파손·방화 영상(약 60GB)을 받으려면 먼저 공간이 필요하다.
- **정리한 것:** 방화 교차검증 이미지·가중치, 물건 탐지기 가중치, hf_cache(약 5.2GB 확보). 방화·물건 탐지기 결과 json은 보존.

## 12. 정상 구성 점검: 서기·걷기 정상 확보 (2026-10-09)

- **질문:** 정상을 서기·걷기로 한 것이 맞는가, 매장이동 중심으로 바꿀까.
- **구성 확인:** 6클래스 학습의 정상 창 44,932개 중 약 89%는 행동 영상의 사건 밖 구간, 약 11%(4,768)가 매장이동이다. 한 에폭(fold 0 보류)의 정상 샘플은 방화 23%, 전도 19%, 매장이동 18%, 유기 16%, 절도 12%, 파손 12%.
- **매장이동 중심 안 기각 이유:** 매장이동 라벨 809개는 사이트가 DYA·DYB 2곳뿐인데 사건 영상은 7곳(SMA, SMB, SYA, SYB, DYA, DYB, SMC)이다. 정상을 매장이동 위주로 하면 "그 두 사이트 = 정상, 나머지 5곳 = 사건"이라는 배경 지름길이 생길 수 있다. 매장이동_1·_2를 더 받아도 같은 두 사이트다(라벨 이름 분석, 영상은 받지 않음).
- **시각 검수(Claude, 사람 검수 아님, 무작위 120창, 출처별 20):** 서기·걷기·빈 화면 94(78%), 계산대에 앉은 사람이 배경에 있는 창 22(18%, 사건 영상에도 같이 나오는 배경이라 정상으로 허용), 바닥 앉기·쪼그리기·눕기가 섞인 창 3(2.5%), 애매 1. 판정 기록: `output/normal_audit_claude.csv`(사람이 뒤집어 볼 수 있게 보관).
- **관절 규칙 필터 시도와 폐기:** 서 있는 자세를 몸통 수직 비율·허벅지 길이로 가려내는 단순 규칙(직접 정함, 논문 근거 미확인)을 정상 창 2.7만 개에 적용했더니 95%를 탈락시켰고 시각상 멀쩡한 창 60개 중 55개도 탈락(카메라가 위에서 비스듬히 봐서 몸통 수직 비율과 무릎 가림이 맞지 않음). 계산대에 앉은 사람이 있는 창을 걸러 내면 "앉은 점원 = 사건" 지름길이 생길 위험도 있다. 표본에 맞춰 임계값을 조정하는 것은 임의 규칙이라 하지 않고 코드를 삭제했다.
- **결론:** 현재 정상(사건 영상의 사건 밖 구간)은 약 97.5%가 이미 서기·걷기·빈 화면이라 별도 필터나 추가 영상이 필요 없다. 개수 균형은 이미 비슷하다.
- **개선 후보(다음 재학습):** (1) 전도 영상의 정상 창 중 전도 시작 직전 창(표본 #118: 마지막 프레임에 주저앉음)을 애매(-1)로 처리, (2) 정상 출처 개수를 더 정확히 맞출지는 6클래스 5-fold 결과를 보고 결정, (3) 새 환경(교실) 서기·걷기 촬영분은 학습 정상 풀과 평가용을 분리해 추가.
- **한계:** 표본 120창으로 추정한 오염 비율(2.5%)의 95% 신뢰구간은 약 0.5~7%이고, 판정자가 사람이 아니다.

### 12-추가. 사건 직전 정상 창 제외 (2026-10-09, 사용자 결정)

- **표본에서 걸린 바닥 장면 3창은 직전이 아니었다:** 사건 시작보다 27~80표본(9~27초) 앞이라 직전 제외로는 빠지지 않는다. 이 3창은 이 규칙의 대상이 아니고, 표본 오염 2.5%(95% 구간 약 0.5~7%)는 그대로 둔다.
- **구현:** `finetune_s3d.py`의 `PRE_EVENT_MARGIN`(표본 수, 기본 0 = 기존 동작). 학습의 정상 샘플에서만 빼고 채점(OOF)은 그대로 둔다(채점에서 빼면 직전 경보가 오경보에서 빠져 점수가 부풀기 때문). 결과 폴더는 `finetune_s3d6_pre48`처럼 따로 저장. 기본값에서 한 에폭 구성이 수정 전과 같음을 지문으로 확인(4·6클래스).
- **효과(48표본):** 정상 창 44,932개 중 16,289개(36%) 제외(유기 47%, 전도 32%, 절도 51%, 파손 53%, 방화 33%). 한 에폭 정상 개수는 나머지에서 채워 유지(fold 0: 방화 3,224·전도 2,511·매장이동 2,086·유기 1,745·절도 1,076·파손 1,052).
- **미정:** 이 정상 구성으로 다시 학습할지(A 5-fold + 최종, 약 7시간)와 순서. 현재 진행 중인 A는 옛 정상 구성이라 기준선으로 쓸 수 있다.
- **직후 제외 추가(사용자 지적 "사건과 전혀 관계없는 것만 정상"):** `POST_EVENT_MARGIN`(기본 0). 사건 끝 뒤 N표본 안의 정상 창도 학습 정상에서 뺀다. 48표본 기준 직전 16,289개 + 직후 4,419개, 합계 20,708개(46%) 제외. 남은 정상은 약 2.4만 개이며 한 에폭 정상 개수는 유지. 단 남은 정상의 출처 균형이 기울어진다(fold 0 에폭: 전도 3,241·방화 3,225·매장이동 2,086·유기 1,789·절도 777·파손 576). 출처별 개수 상한으로 균형을 맞출지는 미정.
- **현재 진행 중인 6클래스 A(옛 정상 구성, 사건 앞뒤 4~5초만 제외)는 "사건과 전혀 관계없는 정상"이 아니다.** 기본값에서 한 에폭 구성이 수정 전과 같음을 지문으로 확인했고 학습에는 영향이 없다.

## 14. 공식 validation 수치 정리: 어떤 숫자가 무엇인가 (2026-10-13)

공식 validation은 네 번 평가했다(모두 블라인드 아님). 평균 Event F1(엄격, 세 행동 평균)은 아래 순서로 바뀌었고 **최신은 0.892**이다.

| 회차 | 설정 | 전도 / 유기 / 절도 Event F1 | 평균 |
|---|---|---|---|
| 1 | 로지스틱 스택, 동결 후 1회 | 0.920 / 0.922 / 0.764 | 0.869 |
| 2 | 동적 결합(사후 재평가), 임계값 OOF 재현율 0.9 | 0.883 / 0.913 / 0.818 | 0.871 |
| 3 | 동적 결합 + 전도 임계값 4.91(OOF 재현율 0.95 목표), 평활 없음 | 0.941 / 0.913 / 0.818 | 0.891 |
| 4 | 동적 결합 + 전도·유기 이동 평균 m=3, 임계값 전도 4.98 / 유기 2.78 / 절도 3.28 | **0.927 / 0.931 / 0.818** | **0.892** |

- **최신(4회):** 이벤트 Precision / Recall / 오경보 시간당 — 전도 1.000 / 0.864 / 0.00, 유기 0.951 / 0.912 / 0.63, 절도 0.867 / 0.775 / 1.28. train / OOF / 공식 validation 평균 Event F1 = 0.987 / 0.941 / 0.892(차이 +0.094 / +0.048). 정상을 걷기·서 있기로 센 보조 기준 평균 0.918. 창 단위 평균 F1 0.806, 균형 정확도 0.714. 근거 파일: `output/official_val/train_val_gap.md`, `report.md`(2026-10-07 15:52), `행동인식_분석.md` §16-추가2.
- **0.891과 0.892는 같은 가중치에 후처리만 다른 두 설정이다.** 0.891 = 이동 평균 없음(전도 4.91), 0.892 = 전도·유기 이동 평균 m=3(전도 4.98 / 유기 2.78 / 절도 3.28). 이동 평균을 켜면 개발 OOF에서 전도 1.89→0.94, 유기 2.60→1.72 오경보/시간으로 줄지만 경보가 약 4초 늦어진다.
- **서비스는 0.891(평활 없음) 설정을 쓴다 — 사용자 결정(2026-10-07), 알림 지연을 피하려고.** 로컬 서비스 설정 `storeops_ai/training/runs/ours_stack/fusion.json`(전도 4.907 / 유기 4.507 / 절도 3.279, `smooth: 1`)이 이 설정과 같다. 0.892는 평활을 켠 연구 참고 결과이며 서비스에 반영하지 않았다. `export_fusion.py`의 `SMOOTH` 딕셔너리에 이 결정이 주석으로 남아 있다(켜려면 `{1: 3, 2: 3}`).
- **서비스가 판정하는 범위:** 현재 서비스(`storeops_ai`, 설정 `training/runs/ours_stack/fusion.json`)는 전도(쓰러짐)·유기(쓰레기 투기)·절도·정상 네 가지만 판정한다. 파손·방화는 서비스에 없고 6클래스 확장 중인 연구 단계다.
