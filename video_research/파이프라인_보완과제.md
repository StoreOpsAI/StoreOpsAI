# 웹캠 이상행동 인식 파이프라인 보완 과제

- 작성일: 2026-09-16
- 대상 문서: `웹캠_이상행동인식_파이프라인_보고서.docx`
- 근거: `전도.mp4`(1920×1080, 3fps, 60초, 42.7~44.3초 전도)로 시험한 결과와 팀 논의

## 확정된 파이프라인

```
YOLO + 추적(ID 이어 붙이기) → 사람 영역 자르기 → 초 단위 창
→ I3D RGB (AI Hub 학습 + 화질·기하 증강) → 웹캠 라벨 영상으로 미세조정 → 기준값 판정
```

### 기존 보고서에서 바뀐 점

| 항목 | 기존 보고서 | 변경 | 이유 |
|---|---|---|---|
| Optical Flow 스트림 | RGB + Flow 두 스트림 | **제외, RGB만** | 계산·추론 비용 2배, I3D Flow 가중치(TV-L1)와 계산 방식 불일치, 3fps에서 흐름 품질 저하 |
| View-BN | BN 통계만 웹캠 기준으로 재계산 | **제외, 웹캠 라벨 영상으로 미세조정** | 팀 촬영 영상은 라벨을 달 수 있으므로 효과가 더 큰 미세조정 선택 |
| CV-3 분류기 | I3D Flow 특징 + CV-3 | **I3D RGB 전이학습** | Flow 제외에 따라 변경 |
| 증강 | 없음 | **화질 + 기하 증강 추가** | 웹캠 화질 차이 대응, 약간의 시점 변화 대응 |
| 16프레임 창 | 프레임 수로 정의 | **초 단위로 정의** | 아래 2번 |
| 추적 | ID 끊김 대응 없음 | **ID 이어 붙이기 추가** | 아래 1번 |

## 1. 추적 번호 이어 붙이기

### 문제
- YOLO는 프레임마다 사람을 찾을 뿐이고, ID는 추적기가 이전 프레임 박스와 짝지어 붙입니다.
- 사람이 누우면 박스가 세로에서 가로로 급변하고(187×578 → 461×170), 3fps라 프레임 사이 움직임이 크며, 중간에 탐지가 1프레임 빠져(44.7초) 추적기가 짝을 못 찾고 새 ID를 붙였습니다.
  - Deep SORT: 2번이 43.7초에 끝나고 3번이 44.3초에 시작
  - ByteTrack: 2번 → 3번, 45.0초
- 창을 ID별로 만드는 구조라 **실제 넘어짐 구간(42.7~44.3초)이 어느 창에도 들어가지 않았습니다.** 학습 데이터를 만들 때와 실제로 쓸 때 모두 생기는 문제입니다.

### 해결 방법
- 새 ID가 생기면 최근 2초 안에 사라진 ID 중 위치가 가까운 것을 같은 사람으로 이어 붙입니다.
  - 조건 예시: 사라진 지 2초 이내, 박스 중심 거리가 이전 박스 대각선 길이 이내
  - 박스 모양이 아니라 위치로 판단하므로 누워도 연결됩니다. 동시 인원이 적은 무인매장에 적합합니다.
- 자세 규칙 시험에서 이 방식으로 전도 전후가 연결됐습니다.

### 확인 기준
- `전도.mp4`에서 전도 전후가 하나의 ID로 이어지는지
- 넘어짐 구간을 포함하는 창이 최소 1개 생성되는지
- 두 사람이 스쳐 지나갈 때 잘못 이어 붙이지 않는지 (다인원 영상)

## 2. 창을 초 단위로 정의

### 문제
| 영상 | fps | 16프레임의 길이 |
|---|---|---|
| `전도.mp4` (AI Hub 형식) | 3 | 5.3초 |
| 일반 웹캠 | 30 | 0.5초 |
| I3D 사전학습(Kinetics) | 25 | 0.64초 |

- AI Hub로 학습하고 웹캠에서 쓰면 같은 동작이 전혀 다른 속도로 입력됩니다. 각도와 별개인 **시간 간격 차이**입니다.

### 해결 방법
- 창 길이를 초 단위로 정의합니다. 예: "2~4초 구간에서 16프레임 균등 추출" (명세서 FR-EVT-04와 일치)
- 웹캠 영상은 AI Hub와 같은 간격으로 프레임을 뽑아 넣습니다.
- **AI Hub 데이터를 받으면 원본 fps를 가장 먼저 확인합니다.** 3fps가 원본이면 1초 안에 끝나는 동작은 프레임이 2~3장뿐이라 창 길이와 프레임 수를 다시 정해야 합니다.

### 확인 기준
- 설정 파일에 창 길이(초), 창 안 프레임 수, 이동 간격(초)이 분리돼 있는지
- 3fps와 30fps 영상에서 같은 초 구간이 같은 창으로 만들어지는지

## 3. AI Hub 학습 + 웹캠 미세조정

### 문제
- Kinetics 사전학습 I3D 출력은 매장 동작과 맞지 않습니다 (`전도.mp4` 시험).
  - 전도에 가장 가까운 `faceplanting` 점수: 모든 창에서 0.006 이하
  - 걷는 구간 1순위: `skateboarding`, `riding scooter`, `jogging` / 누운 구간 1순위: `situp`
- 매장 이상행동 판단은 AI Hub 라벨로 학습해야 가능합니다.

### 학습 순서
1. AI Hub 실내(편의점, 매장) 사람 이상행동 데이터에서 전도, 절도, 폭행, 유기, 파손과 정상 구간을 뽑습니다.
2. 1번(ID 이어 붙이기)과 2번(초 단위 창) 기준으로 창을 만들고 창마다 라벨 하나를 붙입니다.
3. 증강을 적용합니다.
   - 화질: 블러, 노이즈, 저해상도 후 확대, JPEG 압축, 밝기·대비
   - 기하: 원근 변형, 회전, 크기 변경, 좌우 반전
4. Kinetics 사전학습 I3D(RGB)를 6분류(정상 + 5종)로 전이학습합니다. 클래스 불균형에 대응합니다.
5. 학습·검증·시험은 촬영 회차와 연기자 기준으로 나눕니다 (명세서 NFR-11).

### 웹캠 미세조정
- **촬영:** 실제 설치할 웹캠 위치에서 클래스당 20~30개(정상 포함), 연기자 여러 명, 옷·조명 다양하게
- **분할:** 보정용과 평가용을 연기자나 촬영 회차로 나눕니다. 평가용은 미세조정에 쓰지 않습니다.
- **방법:** 앞부분 층은 고정하고 마지막 층만 웹캠 보정용 영상으로 추가 학습합니다.

### 필요한 것
- **GPU:** 시험 환경은 CPU용 PyTorch입니다. RTX A4000을 쓰려면 CUDA용 PyTorch를 설치해야 합니다.
- **웹캠 촬영 영상:** 보정용과 평가용 (둘 다 라벨 필요)

### 확인 기준
- 클래스별 정밀도·재현율·F1, 혼동행렬 (웹캠 평가용 영상 기준)
- 미세조정 전후 웹캠 평가용 영상 성능 비교
- 기준값별 오탐·놓침 수와 기준값 결정 이유

## 참고: 속도 측정값 (CPU 기준, 기존 보고서 구조로 측정)

GPU에서는 훨씬 빨라지므로 상대 비교용으로만 봅니다. Flow 제외로 아래 표의 Flow 계산과 I3D Flow 비용이 빠집니다.

|---|---|
| YOLOv3 | 322ms / 프레임 |
| Deep SORT | 21ms / 프레임 |

| I3D RGB | 259ms / 창 |
| I3D Flow | 265ms / 창 → **제외** |

## 남은 한계
- **절도:** 물건을 넣는 동작이 정상 구매와 비슷해 모델 구조와 무관하게 어렵습니다. "은닉 의심" 후보 수준으로 정의하는 것을 권장합니다.
- **유기:** 물건을 두고 떠난 뒤 물건이 남아 있어야 판단되므로 짧은 창으로는 한계가 있습니다. 라벨이 버리는 순간인지 확인이 필요합니다.
