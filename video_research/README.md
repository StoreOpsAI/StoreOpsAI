# 영상 모델링 연구 (video_research)

> StoreOpsAI의 영상 기반 이상행동 인식 모델 연구와 개발 과정입니다. 서비스 연동 코드는 `storeops_ai/`(루트)에 있고, 이 폴더는 학습·평가 파이프라인과 의사결정 기록입니다.

무인 매장 CCTV 영상에서 **쓰러짐(전도)·유기·절도** 같은 이상행동이 일어났는지를 찾아 알림을 보내는 시스템의 인식 모델과 개발 과정입니다.
목표는 사람을 구별하거나 다시 찾는 것이 아니라 **행동 자체**를 인식하는 것입니다.

- 모델: 사람 추적(YOLO11n) → S3D 영상 분류기 2개(화면 전체 A, 사람 크롭 C1) → 동적 결합 → 이진 경보
- 평가: AI Hub 공개 데이터, 날짜 단위 5-fold OOF와 공식 validation 1회(동결 후)
- 이 폴더에는 **학습 가중치와 원본 데이터를 올리지 않았습니다**(AI Hub 이용 약관 확인 전, 용량). 서비스가 쓰는 가중치의 해시는 연동 브랜치의 `WEIGHTS.sha256`에 있습니다.

## 결과: 각 숫자가 무엇인가

공식 validation 342개 영상(전도 81, 유기 80, 절도 80, 매장이동 101)을 이벤트 단위로 평가한 결과입니다. **같은 A·C1 가중치**에 후처리(이동 평균 여부, 임계값)만 달리한 두 설정입니다. 임계값은 모두 날짜 5-fold OOF에서 정해 동결했습니다.

### 서비스 설정 (즉시 알림, 이동 평균 없음): 평균 Event F1 **0.891**

임계값(로그 오즈) 전도 4.91 / 유기 4.51 / 절도 3.28. 알림이 늦어지는 것을 피하려고 이동 평균을 끈 설정이며, 서비스가 실제로 쓰는 값입니다.

| 행동 | Event Precision | Event Recall | Event F1 | 오경보/시간 (엄격) |
|---|---|---|---|---|
| 전도 | 1.000 | 0.889 | 0.941 | 0.00 |
| 유기 | 0.941 | 0.887 | 0.913 | 0.81 |
| 절도 | 0.867 | 0.775 | 0.818 | 1.28 |
| **평균** | | | **0.891** | |

### 참고: 이동 평균(m=3)을 켠 설정: 평균 Event F1 **0.892**

임계값 전도 4.98 / 유기 2.78 / 절도 3.28, 전도·유기에 과거 3개 창 평균을 적용. 오경보가 줄지만 **경보가 약 4초 늦어져서** 서비스에는 쓰지 않습니다(연구 평가로만 사용).

### 숫자별 설명

| 숫자 | 무엇인가 |
|---|---|
| **0.891** | **서비스 설정**의 공식 validation 평균 Event F1(3회째 사용). 이동 평균 없음, 즉시 알림 |
| 0.892 | 같은 가중치에 이동 평균 m=3을 켠 설정의 평균 Event F1(4회째 사용). 오경보 감소, 지연 약 +4초. 서비스에는 쓰지 않음 |
| 0.936 / 0.941 | 두 설정을 각각 안 본 날짜 5-fold(개발 OOF)에서 평가한 평균 Event F1(서비스 설정 / 평활 설정). 임계값을 정하는 데 쓴 데이터라 약간 낙관적 |
| 0.988 / 0.987 | 학습에 쓴 영상으로 다시 평가한 값(재대입, 서비스 / 평활). 가장 낙관적이라 참고용 |
| +0.097 / +0.045 (서비스), +0.094 / +0.048 (평활) | 평균 Event F1 차이: 학습 − 공식 validation / 개발 OOF − 공식 validation. 안 본 날짜로 갈 때 내려간 만큼 |
| 0.918 | 정상을 "걷기·서 있기" 영상(매장이동 101개)만으로 센 보조 기준의 평균 Event F1(두 설정 모두 0.918). 평가 뒤에 추가한 정의라 주 지표가 아니다 |
| 0.00 / 0.81 / 1.28 (서비스), 0.00 / 0.63 / 1.28 (평활) | 정상 시간당 잘못 울린 경보 수(전도 / 유기 / 절도). 엄격 = 다른 행동 영상의 경보도 오경보로 센다 |

- **Event Precision**: 울린 경보 구간 중 실제 사건과 겹친 비율. **Event Recall**: 사건이 있는 영상 중 경보가 사건 구간과 겹친 비율. **Event F1**: 두 값의 조화평균.
- 6클래스(전도·유기·절도·파손·방화 + 정상)로 확장 중이며 위 표와 숫자에 포함하지 않았습니다. 아직 서비스에는 들어가 있지 않습니다.
- 근거 기록: `의사결정_정리.md` §14, `행동인식_분석.md` §16-추가·§16-추가2, `official_val/train_val_gap.md`(평활 설정 최종 기록, 연구 기록 폴더).

### 6클래스 확장 결과 (개발 OOF 기준, 공식 validation 전)

전도·유기·절도·파손·방화 + 정상 6클래스로 확장 중이며 **서비스에는 아직 들어가 있지 않습니다.** 날짜 5-fold OOF 기준이고 공식 validation은 아직 쓰지 않았습니다. A(화면 전체)와 C1(사람 크롭)을 서비스와 같은 동적 결합으로 합쳤습니다.

| 행동 | Precision | Recall | Event F1 | 오경보/시간 | A 단독 F1 / 오경보 |
|---|---|---|---|---|---|
| 전도 | 0.966 | 0.959 | 0.963 | 0.62 | 0.953 / 1.32 |
| 유기 | 0.951 | 0.903 | 0.926 | 1.61 | 0.922 / 2.48 |
| 절도 | 0.837 | 0.918 | 0.876 | 2.95 | 0.783 / 6.87 |
| 파손 | 0.999 | 0.906 | 0.950 | 0.03 | 0.946 / 0.20 |
| 방화 | 0.904 | 0.948 | 0.925 | 1.83 | 0.896 / 2.22 |
| **평균** | | | **0.928** | | A 0.900, C1 0.914 |

- 개발 OOF 점수는 공식 validation보다 낙관적입니다(4클래스는 OOF 0.941이 공식 validation 0.892로 내려갔습니다). 6클래스의 train–validation 차이와 공식 validation 평가는 다음 단계입니다.
- **새 장소 일반화는 제한적입니다.** 장소를 하나씩 통째로 빼는 평가에서 유기·절도·방화의 재현율이 DYA, DYB, SMC에서 크게 떨어졌습니다(예: 방화 DYA 0.60 → 0.20, 유기 DYB 0.91 → 0.48). 전도와 파손은 비교적 안정적이었습니다.
- 정상 구성을 "서 있기·걷기" 위주로 직접 검수한 구성(Claude 시각 검수, 사람 검수 아님)도 시험했지만 기준선보다 낫다는 증거를 얻지 못해 채택하지 않았습니다.
- 자세한 표와 해석은 [`행동인식_분석.md`](행동인식_분석.md) §20, 결정 과정은 [`의사결정_정리.md`](의사결정_정리.md) §13~15를 봅니다.

### 서비스 반영 현황

- **서비스는 현재 전도(쓰러짐)·유기(쓰레기 투기)·절도·정상 네 가지만 판정합니다.** 파손·방화는 서비스에 들어가 있지 않고, 6클래스로 확장 중인 연구 단계입니다.
- 서비스의 판정 설정 파일은 `storeops_ai/training/runs/ours_stack/fusion.json`(A·C1 동적 결합, 행동별 임계값)입니다. 값은 전도 4.907 / 유기 4.507 / 절도 3.279(로그 오즈), 이동 평균 없음(`smooth: 1`)으로 **위 "서비스 설정(0.891)"과 같습니다.** 사용자 결정(2026-10-07)으로 알림 지연(약 4초)을 피하기 위해 이 설정을 쓰며, 이동 평균을 켜는 설정(0.892)은 서비스에 반영하지 않았습니다.

### 알려진 한계 (결과와 항상 같이 밝힙니다)
1. **공식 validation을 여러 번 봤습니다**(결합 방식·전도 임계값·이동 평균을 정하며 4회). 완전한 blind 평가가 아닙니다.
2. 공식 validation의 정상은 매장이동(걷기·서 있기)뿐이라 반품·손 전달 같은 어려운 정상이 없어 오경보가 낙관적입니다. 임계값을 안 본 fold에서 평가한 개발용 OOF 오경보(전도 1.84, 유기 2.60, 절도 2.33/시간, 재현율 0.90~0.94)가 더 보수적인 참고치입니다.
3. **같은 매장·다른 날짜** 평가라서 새 장소에서의 성능은 측정되지 않았습니다. 강의실 웹캠에서는 유기가 뜨지 않았습니다.
4. 절도는 정상 쇼핑의 "물건 집기"와 겉모습이 비슷해 오경보가 가장 많습니다(후보 알림 수준).
5. 최종 모델은 전체 개발 데이터로 학습해서 OOF가 없고, 임계값은 fold 모델 OOF로 정했습니다.
6. (확장 중인 6클래스) 파손·방화는 날짜 격리를 하지 못했고, 정상 창 일부는 Claude가 눈으로 검수한 것이며 **사람 검수가 아닙니다**.

## 개발 과정에서 지킨 원칙

- **누수 방지:** 한 영상에서 만든 모든 창과 같은 촬영 회차·다중 카메라는 같은 split에 둡니다. 창 단위 무작위 분할은 하지 않습니다. 증강은 학습에만 적용합니다.
- **임계값은 측정으로:** 임의 값을 쓰지 않고 OOF에서 정합니다. 공식 validation은 동결 후 평가에만 씁니다.
- **방법은 선행 연구 먼저:** 방법을 정하기 전에 근거 논문을 확인해 기록하고, 직접 근거가 약한 부분은 "근거 약함"으로 표시합니다.
- **가짜 라벨 금지:** 라벨이 없으면 규칙으로 만들어 쓰지 않고 검수를 전제로 합니다.
- **버린 것도 기록:** 효과가 없던 시도(예: 물건 새로 등장 AND 조건, 프레임 차이 특징, 손 크롭, 사건 직전·직후 정상 제외)와 이유를 남겼습니다.
