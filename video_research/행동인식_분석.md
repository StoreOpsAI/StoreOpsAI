- 기록일: 2026-09-21
- 데이터: AI Hub 실내(편의점, 매장) 사람 이상행동(71550) 유기·절도·파손·방화, 구매행동(71549) Validation 반품 30개
- 공식 validation은 모든 실험에서 제외했다(특징도 뽑지 않음). 설정 동결 후 한 번만 최종 시험한다.

## 1. 누수·과적합 방지 장치

| 막는 것 | 방법 |
| --- | --- |
| 세션 누수 | 촬영 세션 단위 5-fold. 한 세션이 학습과 dev에 같이 있으면 즉시 중단 |
| 다중 카메라 누수 | 같은 촬영의 다른 카메라 영상은 한 세션으로 묶음 |
| 증강 누수 | 증강(좌우 반전·밝기·확대 자르기)은 항상 적용하되 학습 쪽 샘플에만. dev는 원본만 |
| 차원 축소 누수 | PCA 기준은 각 fold 학습 데이터로만 계산, dev는 투영만 |
| 배경 암기 | 정상 클립을 같은 영상의 사건 전후 2초 밖에서 추출 |
| 숨은 누수 확인 | 라벨을 섞은 대조 실험 → 클래스별 F1 0.09~0.33 (찍기 수준, 통과) |
| 설정 선택 편향 | threshold 0.5·학습 설정 고정, dev로 고르지 않음 |

| --- | --- |
| S3D (Kinetics) | 0.877 |
| VideoMAE-B (Kinetics) | 0.887 (transformers 5의 q/v bias 누락을 보정한 값) |

X-CLIP을 백본으로 쓴다. 0.947은 정상 예시가 걷기·서기뿐인 쉬운 조건의 숫자다(4절 참고).

## 3. 유기: 행동 + 새 물건 결합 (train 영상 30개, 30분, 유기 47건)

| 방식 | 재현율 | 오경보 | 분당 오경보 |
| --- | --- | --- | --- |
| 새 물건 감지만 | 0.83 | 56 | 1.9 |
| 행동 판정기만 | 0.98 | 34 구간 | 1.1 |
| **행동 AND 새 물건 (사건 단위)** | **0.81** | **10** | **0.33** |

새 물건 감지기 개선 효과(결합 오경보 63 → 35 → 10):
- 사람이 근처를 떠난 뒤에만 확정 → 팔다리·그림자 오탐 제거
- 테두리 윤곽선으로 새로 놓인 물건(added)과 원래 물건이 치워진 자리(removed) 구분 → 오탐 62개 제거, 정답 손실 1개
- 같은 사람의 연속 양성 구간을 사건 하나로 집계

## 4. 행동별 판정기 (X-CLIP + PCA 32 + 선형, one-vs-rest)

학습 클립: 유기 112, 절도 89, 파손 90, 방화 69, 정상 257(반품 30 포함). 각 판정기의 음성은 정상 + 다른 행동 전부.

| 행동 | F1 (PCA 32) | train-dev 차이 | 판단 |
| --- | --- | --- | --- |
| 방화 | 0.91 | 0.06 | 불이 아닌 사람 동작·은박 쟁반을 볼 가능성 → 불·연기 탐지 필요 |
| 절도 | 0.66 | 0.11 | 손-선반 출입 + 숨김 + 결제 기록 결합 필요 |
| 파손 | 0.62 | 0.11 | 물건 상태 변화 근거 필요 |
| 유기 | 0.46 | 0.13 | 다른 행동과 섞으면 "숙이면 유기" 착각이 드러남 → 새 물건 확인 필수 |

- PCA 비교(512·64·32·16): 512차원은 train-dev 차이 0.17~0.52, 32차원은 0.06~0.13이며 F1은 같거나 더 좋다. 32를 채택했다.
- 정상 클립 오탐률(32차원): 반품 27%, 방화 영상 29%, 절도 38%, 유기 50%, 파손 51%. 판정기는 후보를 넓게 잡는 1차 필터로 쓰고, 정밀도는 근거 모듈로 올린다.

## 5. 절도: "사람이 지나간 뒤 물건이 없어짐"만으로는 부족

train 절도 영상 30개(30분)에서 치워진 자리 감지:

| 항목 | 결과 |
| --- | --- |
| 사건 31건 중 1번 이상 잡음 | 19건 (61%) |
| 훔친 상품 92개 개별 | 30개 (33%) |
| 무관한 치워진 자리 오탐 | 81개 (분당 2.7) |

원인: 같은 상품이 수북이 쌓여 있어 하나를 빼도 빈자리가 보이지 않고, 라벨 상품 박스는 이미 손에 든 위치다.

채택한 절도 판정:

```text
손이 선반 구역에 들어갔다 나옴 (관절 추정 손목 + shelf_zones)
 ├─ 가방·옷에 넣음/숨김 (절도 판정기)             → 절도 후보
 ├─ 손에 든 채 출구로 나감 + 결제 기록 없음 (DB)  → 절도 후보
 └─ 결제 / 선반에 되돌림                          → 정상
```

사람을 구별하지 않도록 결제 대조는 구역·상품·수량 단위로 한다. DB 설계서에 `shelf_zones`, `payment_items` 추가가 필요하다(미반영).

## 6. 방화: 불 탐지

방화 라벨 박스는 불이 아니라 사람이고, 불은 바닥 은박 쟁반 위의 작은 불이다. 현재 판정기는 불을 보지 않는다.
불·연기 탐지 모델(공개 화재 데이터셋)을 근거 모듈로 붙이고, 불이 있으면 사람 동작과 무관하게 경보한다. 우리 방화 영상에서는 "사건 구간에 불을 잡았나"로만 평가한다.

## 8. 유기 오경보: 물건 확인 추가와 다른 행동 영상 측정 (2026-09-23)

새 물건 영역을 YOLO-World(열린 어휘)로 다시 보고 물건이 검출될 때만 인정하는 확인 단계를 추가했다(`models/object_verifier.py`).
여백 1.0·점수 하한 0.05는 아래 유기 train 30개에서 골랐으므로 재현율은 약간 낙관적이다. 세션 dev 분할로 다시 골라야 한다.

| 방식 | 유기 재현율 | 유기 영상 오경보/분 | 다른 행동 영상 오경보/분 | 전체 144분 |
| --- | --- | --- | --- | --- |
| 새 물건 + 확인 | 0.79 | 0.30 | 1.97 | 1.62 |
| 행동 AND 새 물건 | 0.81 | 0.33 | 1.47 | 1.24 |
| **행동 AND 새 물건 + 확인** | 0.77 | 0.07 | 0.73 | **0.59** |

- 다른 행동 영상: 절도·파손·방화 train + 구매행동 반품, 114개 114분. 행동 끝단은 유기 train 전체로 학습(이 영상들은 유기 학습에 쓰지 않음).
- 행동 판정기는 유기 영상에서는 효과가 작지만 다른 행동 영상 오경보를 크게 줄인다 → 유지한다.
- 집계 단위 차이: 결합 방식은 사건(같은 사람 연속 구간) 단위, 새 물건 방식은 검출 단위.

남은 오경보 83건(결합 + 확인)을 눈으로 분류한 결과:

| 원인 | 건수 | 해결 방향 |
| --- | --- | --- |
| 실제 다른 사건(파손 후 바닥 상품 20, 방화 쟁반·불 20) | 40 | 사건 종류 판정 — 오경보가 아니라 맞는 파손·방화 경보로 바뀜 |
| 선반 상품 이동 | 16 | 카메라별 구역 설정 |
| 계산대 물건(계산할 상품, 단말기) | 12 | 카메라별 구역 설정 |
| 잡음(포스터, 그림자, 케이블) | 9 | back-tracing: 물건이 생길 때 그 자리에 사람이 있었나 |
| 사람 일부(앉은 점원, 손) | 6 | 사람 검출기 개선(11n → 11s/m, 누락률 측정) |

합성 테스트(반품 영상 3개에 유기 물건 3종을 붙임, 스크립트는 저장하지 않음): 18개 중 16개 경보. 놓친 2개는 물건이 화면 가장자리에 잘린 경우.

결정 사항과 다음 할 일:
- 주먹구구 패치(같은 자리 IoU 재경보 억제, 확인 어휘에 person 추가)는 쓰지 않는다. 원인 단위로 고친다.
- 유기와 파손은 물건 출처로 가른다: 유기 = 사람이 장면 밖에서 가져온 물건, 파손 = 장면 안 물건이 떨어짐(같은 시각 선반에 '치워진 자리'가 생김 → removed + added 짝).
- 제안 순서: 구역 설정 → 파손 판정(출처 짝) → 방화 판정(불·연기 검출기) → back-tracing·사람 검출기. 단계마다 유기 재현율을 함께 잰다.
- 미결정: 유기 기준을 "사람이 두고 간 물건"으로 좁힐지, 구역 라벨을 수동으로 그릴지 자동으로 찾을지.
- 아직 `Path1BehaviorPipeline`에 연결하지 않았다. 공식 validation은 쓰지 않았다.

## 8-1. 파손: 판정기 AND 새 물건 여러 개 (2026-09-23)

파손 영상은 상품을 바닥에 던지는 장면이다. 라벨의 `object_tool`은 정의만 있고 박스가 없어 시간 기준으로만 평가했다.

물건 근거 단독(`eval_broken_evidence`, 5초 창): 창마다 새 물건 수, 사람 박스 밖 프레임 차이, 치워진 자리를 봤다.
세 근거 중 둘이 켜지면 경보로 할 때 재현율 0.70, 오경보 분당 0.9~1.4였다. 프레임 차이는 3fps에서 사건과 정상이 구분되지 않았다.
치워진 자리 짝(added + removed)도 재현율 0.33으로 약하다. 8절에서 말한 '출처 짝'으로는 가르기 어렵다.

결합(`eval_broken_fusion`): 파손 판정기(X-CLIP + PCA 32 + 선형, 세션 5-fold, 증강은 학습 쪽만) 양성 창의 시작부터 끝 + 10초 사이에 새 물건이 N개 이상 생기면 경보. 음성은 파손 영상의 사건 전 5초~후 20초 밖 구간과 정상 구매행동(반품 30개)이다.

| 새 물건 N | 파손 재현율 | 파손 영상 정상 구간 오경보/분 (9.6분) | 반품 오경보/분 (30분) |
| --- | --- | --- | --- |
| 0 (판정기 단독) | 0.97 | 1.77 | 0.87 |
| 1 | 0.87 | 0.83 | 0.67 |
| **2** | **0.80** | **0.10** | **0.30** |
| 3 | 0.67 | 0.10 | 0.10 |

- N=2가 균형점 후보다. 같은 train 영상으로 고른 값이라 세션 dev 분할로 다시 확인해야 한다.
- 정상 구매 음성은 반품뿐이다. 선택·시험·구매·비교 원천 영상을 받으면 음성을 늘린다.

### 방향 전환: "물건을 집어서 던지는 동작"으로 판단 (2026-09-23)

파손을 물건 상태 변화보다 사람 동작(집기 → 던지기)을 중심으로 판단한다. 새 물건은 던진 뒤에 확인하는 근거로 둔다.

타당성 확인(라벨 관절 좌표, 사람별 값을 몸통 길이 목-골반으로 나눔, 3fps 연속 프레임 사이 손목 이동량):

| | 사람 수 | 최대 손목 속도 p10 / p50 / p90 | 팔 뻗음 최대 p50 |
| --- | --- | --- | --- |
| 파손 사건 | 30 | 0.79 / 1.33 / 1.70 | 1.22 |
| 반품 사건(정상) | 159 | 0.09 / 0.18 / 0.49 | 1.13 |

- 최대 손목 속도가 0.73 이상이면 파손 사건 인물은 90%가 걸리고 반품 인물은 5%만 걸린다. 0.97 이상이면 80% 대 1%다.
- 팔 뻗음은 거의 갈리지 않는다. 손목 속도가 핵심이다.
- 라벨 관절은 이상적인 값이다. 실제로는 관절 추정 모델(YOLO-pose)의 흔들림이 3fps에서 가짜 속도를 만들 수 있으므로 모델 추정값으로 다시 확인해야 한다.
- 반품 159명에는 서 있기만 한 사람도 포함된다. 파손 30명은 사건 인물이다.

파손 로직 초안: ① 집기(손목이 선반 구역에 갔다 돌아옴) → ② 던지기(몇 초 안에 손목 속도 급증, 약 0.8 이상) → ③ 확인(이후 바닥에 새 물건 1~2개 이상). ②는 필수이고 ①이나 ③ 중 하나 이상이 더 켜져야 파손.

## 8-2. 행동별 결정 사항 (2026-09-23)

| 행동 | 결정 |
| --- | --- |
| 절도 | 손-선반 구역 출입 + 숨김(판정기). 결제 DB 대조는 MVP에서 제외 |
| 파손 | 집기 → 던지기(손목 속도) → 바닥 새 물건 확인 (8-1) |
| 방화 | 불·연기 탐지 단독 경보 |
| 폭행·전도 | 현재 데이터로 학습(같은 영상 평온 구간을 정상으로). 한 장소(PLACE07) 편향은 감수 |
| 유기 | 보류. 결합 + 확인이 현재 기준(8절). 구역 설정 방식은 미정 |

다음 할 일: YOLO-pose(`yolo11s-pose.pt`)로 파손 30개·반품 30개의 손목 속도를 다시 재서 라벨 관절 결과와 비교한다.

## 9. 재현 명령 (`storeops_ai_fr_evt/`에서)

```bash
python -m pipelines.compare_backbones                     # 백본 비교
python -m pipelines.eval_new_object                       # 새 물건 감지기
python -m pipelines.eval_abandon_fusion                   # 유기 결합 평가 (--verify: 물건 확인 추가)
python -m pipelines.eval_new_object --verify              # 새 물건 + 물건 확인
python -m pipelines.eval_abandon_false_alarms             # 다른 행동 영상 유기 오경보 (방식별)
python -m pipelines.eval_broken_evidence                  # 파손 물건 근거 단독 (프레임 캐시 생성)
python -m pipelines.eval_broken_fusion                    # 파손 판정기 AND 새 물건 (위 캐시 사용)
python -m pipelines.eval_broken_keypoints                 # 파손 던지기: 라벨 관절 손목 속도 (파손 vs 반품)
python -m pipelines.prepare_behaviors                     # 행동 통합 클립
python -m pipelines.prepare_purchase_negatives --output-dir output/behavior_training --normal-label 정상
python -m pipelines.cv_behaviors --manifest output/behavior_training/samples_purchase.csv \
       --output-dir output/behavior_cv_purchase --pca 32 64
python -m pipelines.make_abandon_composites               # 반품 영상 + 유기 물건 합성(내려놓은 사람 없음 = 음성)
```

### 공통 분할 (`storeops_ai_fr_evt/data/splits.json`, `pipelines/make_splits.py`)

- 모든 모듈이 같은 5-fold를 쓴다. 그룹 = **촬영 날짜**(AI Hub는 한 세트장에서 날짜별로 찍어, 같은 날은 행동이 달라도 조명·배우·카메라 배치가 같음). 31개 날짜, 152개 영상·클립(유기·절도·파손 30, 방화 24, 반품 30, 전도 8)
- fold k를 평가할 때 fold k의 영상(다른 행동의 음성 포함)은 학습·어려운 음성 수집·임계값 확인에 쓰지 않는다. 날짜가 두 fold에 걸치지 않는지 자동 검사
- 행동 학습은 다른 행동 영상을 반드시 음성으로 넣는다. 행동 판정기는 앞으로 한 모델에서 행동별로 따로 켜지는 다중 라벨(행동별 sigmoid)로 같이 학습한다(파손 직후 유기처럼 동시에 해당할 수 있음). 기존 X-CLIP 판정기의 세션 fold는 이 분할로 옮겨야 함(미완)

### 12-1. 매장이동 정상 추가 (2026-09-29)

매장이동 train 123개 중 공식 val과 촬영 날짜(07-18, 10-19)를 공유하는 91개는 격리하고, 나머지 32개(08-13, 10-09, 10-23; 160분, `data/normal_manifest.json`)를 정상으로 학습·오경보 측정에 넣었다. val 101개는 미사용. 이 클립의 사람은 모두 정상으로 본다.

- 일반 매장 걷기·계산대 장면(매장이동)에서는 C 오경보가 없다. 반면 전도 영상 정상 구간(바닥 앉기·무릎 꿇기)의 오경보는 매장이동을 넣기 전(23건, 0.112/분)보다 늘었다: 쉬운 정상(서 있음·걷기)이 정상 클래스를 채워 어려운 정상(바닥 앉기)의 비중이 줄어든 것으로 보인다(추정, 미검증).
- 오경보 원인 분석(C, 23건): 바닥에 앉기·무릎 꿇기·손 짚고 숙이기 약 13건, 계산대 점원(카메라 근접, 몸 일부만 보임) 약 9건, 이미 누워 있는 1건(라벨 누락 가능). 누움과 앉음은 이미지 좌표(몸통 세로성 0.43 vs 0.67, 박스 세로/가로 0.61 vs 0.82)가 겹친다(높은 카메라 시점). 관절 특징 56차원에 선형 대신 작은 MLP를 쓰면 사람 단위 누움 F1이 0.863 → 0.966(오분류 3415 → 585)으로 오르는 것을 확인(설정 사전 값, 튜닝 안 함; dev 결과를 본 뒤 고른 방법이라 낙관적일 수 있음, 클립 단위·매장이동 평가는 미완).

**해석**: 재현율은 유지됐고(전도 클립 81/81), 오경보는 일반 매장 정상에서 0.016/분이다. 서비스 목표(카메라당 하루 10건 이하 ≈ 0.007/분)보다 약 2배 크다. 사람 단위 정밀도가 dev(0.989)보다 낮은 것(0.939)은 매장이동 정상에서 나온 오경보 8건의 영향이다. 이 결과를 보고 설정·임계값·학습 데이터를 고치지 않는다(AGENTS.md 규칙 7). 개선하려면 새 학습 데이터(남은 train 클립, 격리한 매장이동 91개를 val 없이 재분할 등)와 새 시험 데이터가 필요하다. 웹캠 환경 성능은 미확인.

## 13. 유기 정리 (2026-10-07)

**정의:** 사람이 들고 있던 물건을 내려놓고 떠나는 것만(CLAUDE.md 행동 판단 기준). 사람 없이 물건이 생기거나 사람이 서 있던 자리에 물건이 남는 것만으로는 유기가 아니다.

**현재 구성:** 서비스 모델은 S3D 4클래스 하나(A안, 화면 전체 224×224, 4초 창·2초 간격, 24프레임). 사람 크롭 모델(C1)은 5-fold OOF까지 있고 최종 학습은 진행 중. 물건 탐지기는 서비스에 아직 없다.

**OOF 결과(날짜 5-fold, 재현율 ≥0.9에서 오경보/시간, 목표 약 0.42):**

| 방법 | 오경보/시간 | 비고 |
|---|---|---|
| A, 단일 창 (원 로그오즈 점수, abandon_gate 평가) | 2.97 | 평가 경로가 달라 아래 표와 직접 비교 불가 |
| A (로지스틱 결합 평가, ensemble_eval) | 7.62 | |
| C1 | 7.66 | |
| A+C1 | 4.46 | 재현율 0.905. 재현율 0.95에서 9.06 |
| GRU, A+C1 로짓, K=15 | 3.07 | K=1은 4.32 |
| GRU, A 로짓만, K=15 | 3.44 | K=1은 5.02. 서비스 호환 변형 |
| GRU + 사람 수 변화 4채널 | K=30에서 2.18, K=15에서 4.88 | 일관된 이득 없음 |
| 확인 로직 AND 게이트(새 물건 + 사람 떠남), 12에폭 탐지기 | 16.9~25.2 | 재현율 0.9를 넘는 조합은 H=0 4개뿐. **효과 없음** |

평가 경로가 둘이라 숫자 규모가 다르다(로지스틱 재결합 vs 원 점수). 최종 보고서에서는 하나로 통일해야 한다(시도한 방법 수: 게이트 48조합 + GRU 변형 약 10종, 모두 같은 OOF).

**원인 분석(근거 약함, 사례 확인 기반):**
- 4초 창 하나에는 "들고 있다가 내려놓음 → 떠남"이 다 들어오지 않고, 빈 장면에 물건만 남은 창은 원래 있던 물건과 구분되지 않는다.
- 이전 FA 사례 확인에서 오경보 일부는 라벨이 없는 실제 유기였고, 반품의 손 전달도 헷갈렸다(모델 눈 확인이며 사람 검수 아님). 그래서 실제 오경보는 표의 값보다 낮을 수 있다.
- 서비스 쪽 원인: "사람이 추적되지 않은 창은 분류하지 않는다" 조건이 사람이 떠난 뒤(유기 판정 구간)와 쓰러진 사람을 놓친 구간(전도)의 창을 건너뛰었다. 제거했다(path1_behavior._infer_full).

**물건 탐지기(YOLO11s, 클래스 1개 object, COCO 사전학습, 날짜 fold 교차 적합 A/B):**
- 12에폭: 검증 mAP50 약 0.50(A)·0.7(B). 30에폭 재학습(crossA30/crossB30): A 0.649(재현율 0.607), B 0.801(재현율 0.753). 이 검증은 체크포인트 선택용 날짜 10%이며 성능 평가가 아니다.
- 한계: 라벨은 사건 관련 물건뿐이라 같은 장면의 다른 물건은 배경으로 학습됨. 사건 시작 전(들고 있는 동안)의 물건 라벨 없음.
- 30에폭 탐지기로 전체 영상 재추론(objdet30) 후 게이트 재평가(`output/abandon_gate30.log`): 재현율 ≥0.9를 만족하는 조합 4개뿐(모두 H=0), 오경보 17.1~54.3/시간으로 12에폭 때(16.9~25.2)보다 오히려 나쁘다. 탐지기가 좋아져도 '새 물건 AND 사람 떠남' 게이트는 쓸 수 없다고 판단해 폐기. 탐지 특징은 AND 규칙이 아니라 학습형 헤드의 입력으로 쓰는 쪽만 남긴다.

**방법 근거:**
| 방법 | 근거 | 달라진 점 |
|---|---|---|
| 사람-물건 박스 관계를 학습 입력으로 | Chao 외 WACV 2018(HICO-DET), Shan 외 CVPR 2020(손-물건 접촉) — 제목·학회는 §11-추가 기준, 초록 수준 | 손 대신 사람 박스 사용(근거 약함) |

## 14. MVP 기준 결과 (공식 validation, 2026-10-07)

**구성(동결, 서비스에 올라간 것):** YOLO11n 사람 추적 → S3D-A(화면 전체 224) + S3D-C1(창 안 사람 박스 합집합 50% 확장 크롭) → 표준화 + 로지스틱 스택(행동별 로그 오즈 점수) → 이진 경보. 임계값은 날짜 5-fold OOF에서 이벤트 재현율 ≥0.9를 만족하는 후보 중 오경보 창이 최소인 값(전도 3.02, 유기 3.12, 절도 2.07, 로그오즈). 4초 창, 2초 간격, 카테고리별 30초 쿨다운. 카테고리는 정상·쓰러짐(전도)·쓰레기 투기(유기)·절도만(싸움·파손·방화는 학습하지 않아 제외). 물건 탐지기·프레임 대조·GRU·VLM은 쓰지 않는다.

## 15. 물건 기반 보조 신호 비교와 최종 선택 이유 (2026-10-07)

**질문:** 유기("원래 없던 물건이 생김")와 절도("있던 물건이 없어짐")를 S3D(A+C1 스택)에 물건 단서로 보태면 오경보가 줄어드는가? 모두 개발용 날짜 5-fold OOF에서만 비교했고 공식 validation은 쓰지 않았다.

| 시도 | 방법 | 결과(재현율 약 0.9에서 오경보/시간) | 판단 |
|---|---|---|---|
| 기준 | S3D A+C1 스택 | 전도 1.42, 유기 4.46, 절도 8.10 | **채택** |
| 물건 탐지기 관계 특징을 스택 입력으로 (12/30에폭 YOLO, 교차 적합) | 사람-물건 거리·남겨진 물건 등 창 특징 | 전도 1.42/1.46, 유기 4.92/5.57(악화), 절도 4.67/4.44(약 45% 감소) | 절도만 이득. 탐지기가 유기·절도 영상의 사건 물건으로만 학습돼 "장면 표시"로 쓰였을 가능성(shortcut)을 못 배제 → 미채택 |
| 새 물건 AND 사람 떠남 게이트 (S3D 점수 × 직전 N표본에 없던 박스 × 뒤 H표본 사람 없음) | 규칙 결합, 48조합 OOF 탐색 | 12에폭 탐지기 16.9~25.2, 30에폭 17.1~54.3 (S3D 단독 2.97) | 진짜 유기 창을 많이 버려 오경보가 오히려 증가 → 폐기 |
| 프레임 대조(배경 차이) 새 물건/없어진 물건 감지기 (Porikli 2008, Tian 2011 응용) | 장기·단기 배경 차이, 사람 영역 제외 | 정상 영상에서도 added 시간당 306~406건, removed 84~219건(후보 단위). 정답 박스 기준 파라미터 48조합 탐색: 유기 added 재현율 0.7을 지키면 후보 오경보 150건/시간 이상, 오경보를 30건 이하로 줄이면 재현율 0.5 이하. 절도 removed 재현율 0.05~0.37 | 구분력 약함. 선택 설정(밝기 차 15, 유지 6초, 최소 넓이 1000): 유기 재현율 0.71 / 후보 오경보 159건(선택 fold), 0.64 / 170건(보고 fold). 화면 검수에서 정답 위치에 맞게 잡히는 경우(IoU 0.72~0.86)도 있으나 카운터·먼 선반의 변화가 훨씬 많음 → 미채택 |
| GRU로 맥락 결합 | 지난 K개 창 점수 | 전도 1.37→0.85(A 로짓만), 유기 5.0→3.4, 절도 변화 없음 | 서비스 비용 대비 이득이 작아 미채택 |
| 후보 분류기(정답 물건 박스로 프레임 대조 후보 학습) | 코드만 작성, 실행 안 함 | - | 사용자 결정으로 중단 |

**선택 이유(최종 = S3D A+C1 스택 단독):**
1. 사용자 방침: S3D가 놓고 감/가져감을 행동과 함께 학습하고 배경은 사람 크롭이 줄인다. 보조 규칙·탐지기를 얹지 않는다.
2. 물건 기반 신호는 (a) 규칙으로 걸면 진짜 사건을 버리고(게이트), (b) 프레임 대조는 매장의 일상 변화(손님의 물건 집기·점원 정리)를 잡음으로 많이 내며(시간당 150건 이상), (c) 탐지기 관계 특징은 절도에서만 이득이 있고 장면 shortcut 위험이 있다.
3. 시연은 강의실이라 매장 영상으로 맞춘 보조 특징은 의미가 작다.

**남은 과제:** 물건 탐지기 8:2 파인튜닝(작은 물건 재현율 개선, 1920 해상도)은 별도로 진행 중이며, 효과가 확인되면 절도 물건 관계 특징을 다시 평가한다(그때 shortcut 점검 필요).

**삭제한 것:** 프레임 대조 특징·후보 수집 코드와 중간 결과(`nobj`, `cand` 등)는 위 결과만 남기고 삭제했다.

## 16. 결합 방식 비교와 동적 결합 채택 (2026-10-07, 사용자 결정)

## 17. 물건 탐지기: 가려짐 유지(들려서 가려진 물건) 설계 근거와 데이터 확인 (2026-10-07)

**선행 연구(검색으로 존재 확인, 본문은 읽지 않음 — 초록·검색 요약 수준):**

|---|---|---|
| 낮은 점수 탐지도 기존 궤적에 이어 붙여 가려진 대상을 복원 | Zhang 외, "ByteTrack: Multi-Object Tracking by Associating Every Detection Box", ECCV 2022 ([링크](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136820001.pdf)) | 물건 탐지기의 낮은 점수 박스(0.10 이상 저장)를 궤적에 이어 붙이는 데 응용 |

### 20-5. 물건을 쥐고 있는지(쥠/빈손) 라벨과 선행 연구 조사 (2026-10-14, 사용자 결정: 라벨링 안 함)
- AI Hub XML(CVAT)에는 관절 17개(손은 손목 한 점), 행동 구간 마커, 물건 박스(유기 `object_abandon`, 절도 `object_article`, 매장이동 `object_snack` 등)는 있지만 **쥠/빈손 속성은 없다.** 속성은 ID·성별·연령대뿐이다.
- 손 관절과 물건 박스의 거리로 "쥠"을 계산하면 규칙으로 만든 가짜 라벨이라 쓰지 않는다. 사람 검수 표본이 있어야 하는데 사용자가 직접 라벨링을 하지 않기로 했다. **쥠/빈손 판정기와 100DOH 사전학습 탐지기 검증은 보류.**
- 대신 라벨이 필요 없는 방법만 쓴다: 이미 만든 손 크롭(H)을 6클래스 A+C1에 붙여 같은 OOF로 측정하고, 신뢰구간이 겹치지 않을 때만 서비스에 반영한다(4클래스 시험은 §18~19: 절도에서만 일관되게 오경보 감소, 중첩 평가에서 유기는 악화).
- 조사한 선행 연구(§11 표에 기록): Shan 외 2020(100DOH 접촉 상태), Narasimhaswamy 외 2020(손 접촉 분류), Gu 외 2018(AVA, 사람-물건 행동 라벨링 절차), Shopformer 2025와 Skeleton-based Action Recognition of People Handling Objects(자세 기반 + 물건 정보). 오픈소스 자동화로는 ddshan `hand_object_detector`(체크포인트 공개, 라이선스·CCTV 정확도 미확인)가 있다.

### 20-6. 손 크롭(H) 6클래스 시험 — 진행 중, 결론 없음 (2026-10-14, 개발 OOF만, 공식 validation 미사용)
- H = 손목 주변 크롭을 S3D에 넣어 파인튜닝한 세 번째 스트림(§18~19와 같은 방식, 6클래스·기준선 정상). 5-fold 중 fold 0~2까지 학습했고 fold 3부터는 이어서 해야 한다(`finetune_s3d_h6`). **완료 전이라 아래는 확정 결과가 아니다.**
- fold 0, 1만으로 본 중간 확인(`EVAL_H_DIR`, 창 35,529개): A+C1 대 A+C1+H 오경보(시간당) 전도 1.25 [0.71~1.92] 대 1.19 [0.64~1.75], 유기 4.27 [3.15~5.32] 대 4.34 [3.15~5.60], 절도 6.40 [4.82~8.02] 대 4.61 [3.51~5.73](가장 큰 감소지만 구간이 겹침), 파손 0.07 [0.00~0.21] 대 0.00 [0.00~0.00], 방화 0.57 [0.25~1.00] 대 0.96 [0.45~1.45]. 어느 행동도 구간이 겹쳐 현재까지 채택 기준을 못 넘음(fold 2개, 임계값은 이 두 fold 안에서 정함). H 단독은 오경보가 많아(전도 3.83/시간) 보완용으로만 본다.
- 보조 필터 아이디어(A+C1 판정 기본, H는 오경보 걸러내기)의 방향 확인(창 단위, 느슨한 임계값, fold 0·1): 같은 양성 손실 10%에서 제거되는 오경보 비율이 임계값 올리기 대 H 필터로 전도 44% 대 73%, 유기 69% 대 65%, 절도 80% 대 74%, 파손 66% 대 74%, 방화 55% 대 67%. 유기·절도에서는 H 필터가 임계값 올리기보다 낫다는 근거가 없다. 이벤트 단위·운영 임계값 평가가 아니므로 방향 확인에 그친다.
- 평가 코드: `eval_six_fusion.py`, `eval_six_summary.py`가 `EVAL_H_DIR`을 받으면 H 단독·A+H·C1+H·A+C1+H를 함께 비교한다(H 없이 돌린 결과는 기존 `six_summary_base.log`와 동일함을 확인).
- 판단 기준은 기존과 같다: A+C1 대비 오경보 신뢰구간이 겹치지 않을 때만 채택. 현재 후기 결합 A+C1은 시험한 구성 중 최선이지 최적임이 증명된 것은 아니다(타일링, 중간 결합, 이어서 학습, 다른 백본은 미시험).
- 6클래스 공식 validation 평가 스크립트(`score_official_val.py`의 S3D_CLASSES=6 지원, `eval_official_val_six.py`)는 준비만 했고 **실행하지 않았다.** 설정 동결 후 1회 평가한다.
